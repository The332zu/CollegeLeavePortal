# Experiment 1: User Stories
## Project
College Leave Portal
## Aim
To identify and write user stories for a College Leave Portal using Agile Software Development principles.
## Actors
1. Student
2. Faculty
3. HOD
## User Stories
| ID | User Story | Priority |
|---|---|---|
| US-01 | As a Student, I want to log in so that I can access my account. | High |
| US-02 | As a Student, I want to apply for leave with dates and a reason so that my request can be reviewed. | High |
| US-03 | As a Student, I want to view my leave status so that I know whether it is pending, approved or rejected. | High |
| US-04 | As a Student, I want to cancel a pending leave request so that I can withdraw it if plans change. | Medium |
| US-05 | As a Student, I want to view my leave balance so that I know how many leave days remain. | Medium |
| US-06 | As Faculty, I want to review leave requests of up to 3 days so that I can approve or reject them. | High |
| US-07 | As an HOD, I want to review leave requests of up to 10 days so that longer requests can be handled appropriately. | High |
| US-08 | As an approver, I want to provide a rejection remark so that the Student understands the decision. | Medium |
| US-09 | As a user, I want to log out so that my session is not left open. | High |
## Acceptance Criteria
1. Incorrect login credentials must be rejected.
2. Leave requests require valid dates and a reason.
3. The end date cannot be earlier than the start date.
4. A new leave request receives Pending status.
5. Only pending leave requests can be cancelled.
6. Faculty can approve requests up to 3 days.
7. HOD can approve requests up to 10 days.
8. Updated leave status must be displayed.
## Conclusion
User stories define the requirements of the College Leave Portal from the perspective of its users. They will guide system design and testing in subsequent experiments.
